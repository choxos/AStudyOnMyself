# Review record

Version 3.0 of the protocol of A Study On Myself was reviewed by two AI models before it was finalized: GPT-6-Astra (OpenAI), run through the Codex command line tool, and Grok 4.6 (xAI), run through the Grok command line tool, both at reasoning effort xhigh. **This is review by AI models, not peer review by human experts.**

How the review worked:

- Each reviewer received the protocol and a copy of the study software (the Stan model, the R analysis code, the database schema and the web application) in a read-only folder, without any study data, configuration or machine names. The two reviewers worked independently and did not see each other's reports.
- Both received the same instructions, reproduced at the end of this page. They sort every point into must fix (a false statement or one the code contradicts, a statistical error, a missing element without which the study cannot be evaluated or carried out as described, or an internal contradiction), should fix, and minor. A reviewer accepts when no must-fix point remains.
- After each round, the investigator answered every point and revised the protocol. From round 2 on, each reviewer received its own previous report, the response to it, the changes to the protocol and a fresh copy of the software, and marked each earlier point as resolved or not.
- The review ran for four rounds. Grok 4.6 accepted the protocol from round 2 on. GPT-6-Astra's round 4 report left one must-fix point, the order in which the rating page applies the server's answers about the safety rule; it was fixed and tested, and the participant finalized the protocol on 19 September 2026 without a fifth round. After round 4, the protocol text changed only in the administrative information, the revision history, the pilot dates, the tense of the review section and one clarification that the last Grok 4.6 report asked for.
- The reports are shown as the reviewers returned them, in structured form; only the layout is added here. Each version the reviewers received is linked from the table below, and the scripts that ran the review (`peer-review/run-review.sh`, `peer-review/snapshot.sh` and `peer-review/extract.ts`) are kept with the study software. The Codex event logs in `peer-review/` are kept as recorded, except that `extract.ts` replaces paths in the home folder with `~` and leaves out the output of commands that read files outside the review workspace, such as the reviewer tool's own settings and plugins.
